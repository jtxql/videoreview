# 阶段2B：Windows官方Console USB抓包计划

状态：计划待执行。用户已确认同一台Lite在Windows官方Console下全部旋转正常。本轮006L不安装工具、不访问USB、不执行实验。

## 目的与准备

对比官方软件工作时的初始化与Android当前流程，寻找旋转上报条件；不猜测或重放命令。源码证据及未验证假设见 [研究报告](TOURBOX_RESEARCH.md)，阶段2A返回7/0/0/8不代表解锁成功。

记录Windows版本、Console版本、Lite固件（若可见）、产品字符串、bcdDevice和物理端口；序列号仅本地保存或脱敏。CAFE:4001也见于其他型号，不能只凭VID/PID关联。准备官方软件已有配置及动作时间表，不更新固件或改变配置。

先检查是否已有USBPcap/Wireshark及兼容版本；若缺失，安装驱动需另行授权，可能需要管理员和重启。保留官方/usbser驱动，不用Zadig替换。USBPcap捕获URB及载荷，不是物理总线事务分析。参考 [Wireshark USB说明](https://wiki.wireshark.org/CaptureSetup/USB) 和 [USBPcap限制](https://desowin.org/usbpcap/capture_limitations.html)。

## 最小对照

1. W1：退出Console及其后台进程，控制器实际拔出断电；选择正确root hub，从插入前开始捕获，记录空闲、按钮和各旋转控件双向慢转各10步。系统驱动可能仍发送初始化，不称为完全无初始化。
2. W2：再次断电，在独立捕获中固定并记录Console启动/插入顺序，捕获就绪全过程；保持同一配置，重复相同操作及时间标记。只让官方软件正常工作，不另开串口工具或手动发命令。
3. 必要时追加热关闭/重开Console对照，检验初始化状态是否跨会话保留；不把热重开当冷启动。

## 分析和交付

- 先根据物理端口和描述符找到bus/address，重枚举后跟踪新地址；仅按VID/PID过滤会漏掉普通传输。
- EP0：记录setup全部字段、payload、返回状态，区分CDC类请求与厂商请求。
- 0x02 BULK OUT：记录实际完整字节、长度、时序和完成状态；核实八字节/94字节是否出现，不预设必然出现。
- 0x82 BULK IN及0x81 INTERRUPT IN：按操作时间比较原始数据，不预设每次读取是一个事件。
- 配对URB提交/完成，避免重复计数；保留帧号、原始pcapng、动作时间表及工具版本，检查捕获丢包和载荷截断。
- 不提交原始pcapng或个人设备日志到Git。捕获root hub可能包含其他设备数据，分享前只保留必要目标通信并检查敏感信息。

若W2正常但抓不到旋转，先排捕获范围/地址/重枚举错误；若抓到额外配置，先审查语义和风险，再提出单变量Android实验，不直接发送94字节模板。结束后停止捕获、正常退出Console并拔插设备；不保证官方软件不会保存既有状态。
