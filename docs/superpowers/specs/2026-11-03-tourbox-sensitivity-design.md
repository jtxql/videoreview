# TourBox旋转灵敏度：简短设计

日期：2026-11-03。用户确认低灵敏度需更多转动才逐帧、高灵敏度跨多帧/跳更远；本细化设计已获用户确认；实施计划已获用户批准，已按Native顺序实施并完成无设备验证，待真机验收。

## 交互与范围

在TourBox设置中增加Knob、Scroll两个独立滑块。建议五档：0.25×、0.5×、1×、2×、4×；默认1×保持现有行为，保存后统一生效并持久化，取消不生效，恢复默认同时回到1×。不增加主界面控件。

采用固定手动倍率；不根据旋转速度自动加速，不改变视频播放倍速，不改USB数据或007解码事件。

## 动作语义

灵敏度按旋转来源选择Knob/Scroll，但由其当前映射动作决定处理方式：

|映射动作|0.25×|0.5×|1×|2×|4×|
|---|---|---|---|---|---|
|前进/后退一帧|同方向累计4次输入后1帧|累计2次后1帧|每次1帧|每次2帧|每次4帧|
|快进/快退（基础5秒）|每次1.25秒|每次2.5秒|每次5秒|每次10秒|每次20秒|

这里的输入指已识别的旋转事件，不承诺一个物理刻度等于一个输入，也不推断旋转角度。调速、播放/暂停、AB、截图及不执行不放大或重复，保持原先单次行为。按钮按下/释放不受滑块影响。

## 累计与安全

- 逐帧的低倍率余量对两个控制件独立记录；反向转动、该控制件超过1秒无输入、配置改变、停用、USB/播放器会话变化时清零。互相转动不串用余量，不把旧方向欠账带入反向。
- 高倍率逐帧按顺序最多生成4个既有逐帧命令；快进快退合为一次带倍率秒数的SeekRelative，不靠多次相对跳转叠加。不改mpv核心。
- 仍受32项队列、2秒过期和旧会话授权保护，队列不无限膨胀；积压取消/拒绝保留诊断统计，不保证超载时仍执行全部派生动作。
- 保留每个原始字节/语义事件记录。派生动作标明来源和序号，累计待触发不冒充未知原始码，不变更原事件数量。
- 配置采用当前版本格式的可选稳定灵敏度字段，旧配置无字段按1×读取；非法/重复值回默认1×并提示，不重置有效按钮映射。草稿、equals/hash、恢复默认和后台保存均包含两滑块。
