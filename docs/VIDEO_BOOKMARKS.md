# 当前视频的片段书签

版本：0.7.0-clip-bookmarks / 构建20。用户已反馈“已验证”，记为本轮书签功能用户验证通过。

## 操作

1. 打开本地视频，使用屏幕或TourBox标记有效A/B，并选择需要保存的倍速；A/B不必已启用循环。
2. 点击底部“片段书签”，视频暂停。全屏中可点击视频显示进度浮层，再点击“片段书签”。
3. 点击“保存当前A/B”，输入名称并保存。程序读取核心实际倍速，写入成功才更新列表。
4. 点击一项恢复保存的A/B及倍速，从A点开始无限循环；进度条同步显示A/B标记。
5. 改名、删除只影响书签，删除须确认，不会删除视频或清除当前播放区间。仅关闭列表不自动继续播放。

列表只显示当前视频，新书签在前。可保存多个同名或同区间书签，不按名称覆盖。名称为1～40个Unicode码点、去掉首尾空白，不能含换行/控制字符。每视频最多200条、全库2000条，存储文件最多2MiB；满时提示，不自动删旧书签。

## 存储和文件关联

只保存ID、文档URI、名称、A/B、倍速和创建时间，不复制或导出视频。进程级后台串行存储在应用私有`files/video-bookmarks.v1`中，采用版本化文本与AtomicFile；URI/名称使用Base64隔离分隔符，Base64不是加密。普通日志不记录完整URI或文件内容。

覆盖升级与正常重启保留数据；卸载/清数据会删除。书签按完整content URI关联，不凭文件名识别；视频移动、删除、权限丢失或提供方改变URI后可能失联，需重新选择原文件，新URI不自动迁移旧书签。SAF持久授权并非任何提供方都保证可用。相同URI内容被替换不能严格识别，恢复时仍校验实际时长和区间。

读写在worker，UI只读不可变快照；revision拒绝过期修改。写入、改名、删除失败保留输入/旧列表；损坏、超限、未知版本或读取失败停止写入并保留文件。提交前异常走AtomicFile失败路径；提交后无法核对内容时视为“结果未知”并禁写，不继续覆盖。原子文件与回读检查不等于已证明断电或底层磁盘故障下的持久性。

## 播放器和生命周期

ReviewPreset/ReviewRestorePlan独立于USB与界面。恢复使用一个busy操作：校验实际Duration→暂停→清旧B/A→恢复倍速→新A/无限次数/B→精确seek到A→播放。每次native读写前核验core、播放器epoch及交互租约，失败不重试、不伪造回滚；部分写入失败走既有播放器释放路径。

保存快照在核心读取Speed/Duration，避免250ms状态刷新滞后。列表期间撤销旧TourBox待办并暂停播放器事件分发，原USB读取不停止；关闭后正常恢复控制接纳。选中书签关闭窗口但保留单次恢复租约，防止误取消自身或连点重复恢复。后台、销毁、离开页面或播放器换代关闭租约及窗口；保存/恢复的迟到回调不能操作新视频。后台重建只保留暂停意图，不自动重新执行书签恢复，未保存输入不跨进程保留。

USB命令、8/26/94字节、CDC、端点、解码、旋转灵敏度与隔离机制不变，USB-001仍为既有Deferred限制。
