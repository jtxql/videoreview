# TourBox设置与自定义映射

版本：0.6.2-rotary-sensitivity/code19。

## 用户操作

主界面底部“TourBox设置”打开设置对话框，仅显示连接状态、两个灵敏度滑块、12项下拉映射、恢复默认/保存/关闭及版本。没有接口、端点、数据包、原始日志、手动CDC或8/94字节命令入口。

修改下拉框只是草稿，点击保存且写入成功后统一生效。关闭或返回不会悄悄保存；有未保存修改时询问丢弃。恢复默认先重置草稿，仍需保存；保存失败保留草稿，继续使用旧映射。配置存在手机应用私有SharedPreferences中，覆盖升级保留，清除应用数据或卸载会清除设置。

首次启动后台读取设置，未读完前暂不启用TourBox控制；视频屏幕操作不受影响。打开设置暂停视频和播放器事件分发，不主动停止USB读取。设置期间切到后台仍沿用原USB/播放器清理；返回继续草稿，退出设置后的重建播放保持暂停。进程被杀后的未保存草稿不恢复；系统有保存状态并重建宿主时，保留设置/截图造成的暂停意图，不意外自动播放。初始化或播放器忙时暂时禁用设置入口，避免打断正在进行的操作。

## 默认输入

|输入|默认动作|
|---|---|
|Knob顺时针/逆时针|前进一帧/后退一帧|
|Scroll上滚/下滚|快进5秒/快退5秒|
|Knob按下|播放/暂停|
|Scroll按下|循环切换速度|
|Top按下|启用/清除AB|
|C1/C2按下|记A/记B|
|Short、Long/Tall、TourBox按下|不执行|

Long/Tall是实体按钮，不是长按。首版仅一次按下及旋转方向，松开/未知码不执行；不支持长按、双击、组合键、学习模式或多配置档。

## 可选动作

不执行；播放/暂停切换、播放、暂停；前进/后退一帧；快进/快退5秒；速度提高/降低一档、循环五档、直接设置0.1/0.25/0.5/0.75/1倍；记A、记B、启用AB、清除AB、切换AB、回A；截图标注。同一动作可分配给多个输入。速度提高/降低到边界会停在该档，循环切速到1倍后回0.1倍。

截图标注复用当前可见区域功能，进入后暂时停止播放器控制，避免旋转连续打开多个面板；原始USB仍按原规则记录。初始化未就绪、导出或截图编辑期间会拒绝新控制。选文件、视频导出及USB命令不在映射动作中。

## 实现与安全

- TourBoxMapping：稳定字符串ID，不使用enum序号；版本化文本配置，缺失/未知动作/重复项按项恢复默认，未知版本或超长数据整体回退，恢复情况在设置中提示。草稿与活动配置分离。
- TourBoxMappingStore：进程级后台串行读写，SharedPreferences.commit成功才更新快照；失败尝试恢复旧内存值，旧活动映射不变。使用revision拒绝过期覆盖。订阅随宿主生命周期释放，Dialog销毁不影响已成功持久化设置供新宿主读取。
- TourBoxPlayerBinding：同一临界区读取配置并入队，保存新配置提升代次并撤销旧待办/旧授权；普通操作仍executeGuarded。截图有独立来源租约，不因自身暂停分发误取消，但USB、配置或播放器来源变化会失效。
- 队列维持32项、2秒过期；仅旋转产生的连续重复动作优先淘汰，截图/切换等离散动作不因来源是旋转被当作逐帧工作丢弃。满队列仍明确拒绝、记录计数，不变成无界队列或自动停用正常会话。
- MainActivity只保留自动连接、系统权限、attach/detach、后台/销毁回收及后台日志。删除旧Spinner刷新等UI回调，避免仅刷新设置就切换设备/关闭连接。
- USB原始协议、8/26/94字节顺序、端点、输入解码、未知pending隔离不改；USB-001物理拔出恢复限制仍在。后台原始日志与播放器日志仍可在问题排查时通过只读ADB导出，不显示给普通用户。

## 两个旋转控件的灵敏度

Knob、Scroll分别保存0.25×、0.5×、1×、2×、4×，默认1×。倍率跟随物理控制件，只有其旋转映射为前后逐帧或快进快退时生效；按钮按下、截图、AB、播放暂停和所有调速动作仍每事件一次。滑块先改草稿，保存成功才统一应用，取消不应用，恢复默认也将两滑块设为1×。

|倍率|逐帧（同方向事件）|快进/快退距离|
|---|---|---|
|0.25×|累计4个事件走1帧|1.25秒|
|0.5×|累计2个事件走1帧|2.5秒|
|1×|每事件1帧|5秒|
|2×|每事件2帧|10秒|
|4×|每事件4帧|20秒|

事件不等于物理刻度，不推断角度或旋转速度。两控件各自累计，反向（包括映射为不执行的反向）、同控件超过1秒无输入、改配置、停用或USB/播放器换代清空余量；普通播放器busy更新不清空。跳转只发送一个缩放距离的命令，不连续叠加多次seek。

`RotationProcessor`是纯模型，在桥接锁内决定0～4条命令，`Pending`冻结命令和配置/来源代次，每条独立通过原有32项队列、2秒过期和播放器授权。高倍率快速旋转仍可能触发已知积压淘汰策略；不会变为无界队列，也不保证所有物理操作都被播放器执行。received按原语义事件计；admitted/cancelled按派生命令计；低档未形成命令计入ignored并记录ACCUMULATED。QUEUED/ADMISSION携带同一原始seq及part，USB/语义原始日志不重复。

配置仍为version=1，增加可选`knob-sensitivity`及`scroll-sensitivity`稳定字符串字段。旧配置缺项静默采用normal；非法/重复字段只让该灵敏度恢复默认并提示，其他映射保留。普通映射编辑与灵敏度编辑相互保留，后台保存失败继续使用旧活动配置。
