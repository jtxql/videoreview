# 已知问题

## USB-001：物理拔出后异步UsbRequest可能无法确认回收

- 状态：**Deferred**（2026-11-02归档）。
- 范围：当前Android USB Diagnostics，TourBox Lite接口0的0x81异步请求。
- 优先级：不阻塞008播放器基础功能开发；当前不继续调查或修复。

### 已知现象与证据

正常停止能够取得原请求完成，随后request.close、两接口release及connection.close成功；同一地址正常再次open已通过007-Y真机验证，日志明确为NormalReopen及新token。

物理拔出时0x81 requestWait可能返回null，cancel可能返回false，有限回收观察可能持续Null。Android普通广播不提供可核验的物理连接代次；Strict策略下detach归属不能充分关联时，补充回收不执行。未确认pending进入安全隔离，当前进程内可能不能再次打开设备。007-Y证据：422–442行，初次5次Null，资源与线程条件满足，association=Unknown、eligible=false，最终隔离。详见[007最终验收](TOURBOX_INPUT_ACCEPTANCE_007_FINAL.md)。

### 当前处理策略与验收边界

保留现有保守隔离，不强制request.close或connection.close未知pending所需资源，不通过新open绕过进程级独占。

必须区分：**安全隔离按设计生效；物理拔出自动恢复未通过验收；尚不能证明实际发生内核资源泄漏。** cancel=false不是泄漏证明，线程退出也不是请求已取回证明。没有资源趋势测量，不扩大结论。

### 用户可见限制与恢复建议

物理拔出后应用可能显示“已逻辑断开；回收状态未知（隔离）”，并拒绝再次连接。此时停止重连并保留日志。

如需恢复，当前建议完全结束应用进程后重新启动，例如用户通过系统应用设置的“强行停止”后再手动打开。这是建议的恢复操作，**不代表已证明底层资源一定完成释放，也不保证每次恢复成功**。关闭Activity、返回桌面或划掉最近任务都不能描述为可靠的进程终止保证。本轮没有自动执行任何恢复操作。

### 后续处理

维持Deferred，仅在未来出现实际用户体验问题、崩溃或资源累积证据时重新评估，并另立任务。不会为完成007归档而简化协议、删除隔离或启用更宽松的关联策略。5秒拔出后观察和完整压力测试尚未完成，不将其记为通过；它们作为覆盖缺口保留，不阻塞008。
